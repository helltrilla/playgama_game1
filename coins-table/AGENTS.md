# AGENTS.md — правила работы агента над Coins Table

Idle-игра на three.js для Playgama. Разработка идёт по **SDD (spec-driven)** и **TDD**. Код без спецификации и теста не пишется.

## Источники истины (читать перед задачей, по порядку)
1. `docs/PRODUCT.md` — что и зачем делаем, рамки.
2. `docs/ACCEPTANCE.md` — проверяемые критерии с ID (`AC-*`). Каждая фича привязана к ним.
3. `docs/ECONOMY_SPEC.md` — формулы и числа. Единственный источник баланса.
4. `docs/ARCHITECTURE.md` — слои и границы модулей.
5. `docs/SCREEN_SPEC.md`, `docs/DESIGN_SYSTEM.md`, `docs/DESIGN_TOKENS.md` — UI.
6. `docs/PLAYGAMA_INTEGRATION.md` и `docs/PLAYGAMA_COMPLIANCE.md` — SDK и модерация.
7. `docs/TEST_PLAN.md` — как и что тестируем.
8. `docs/DECISIONS.md` — принятые решения (ADR). Не переоткрывай решённое без записи.
9. `docs/ROADMAP.md` — порядок задач и их статус.

Если код противоречит доке, прав док. Если док неполный или спорный: сначала правка дока (и запись в `DECISIONS.md`), потом код. Не угадывай молча.

## Цикл работы над задачей (обязательный)
1. **Spec.** Найди или добавь критерии `AC-*` в `ACCEPTANCE.md`. Задача без критерия не начинается.
2. **Red.** Напиши тест(ы) под критерии. Запусти и убедись, что они падают по правильной причине.
3. **Green.** Минимальная реализация, чтобы тесты прошли.
4. **Refactor.** Чисти код при зелёных тестах.
5. **Verify.** `npm run verify` (lint + typecheck + unit + build). Для UI и Bridge ещё `npm run test:e2e`.
6. **Docs.** Обнови затронутые доки, поставь статус в `ROADMAP.md`, отметь `AC-*` в `TEST_PLAN.md` (трассировка AC → тест).
7. Только после этого говори «готово» и покажи вывод команд.

## Жёсткие правила
- **Чистое ядро.** `src/core` без three.js, DOM и Bridge. Детерминированно: время (`Clock`) и случайность (`Rng`) передаются снаружи. Это делает логику тестируемой.
- **Три слоя.** `core` (логика) ← `platform`/`scene`/`ui` (адаптеры). Обратные импорты запрещены (см. `ARCHITECTURE.md`).
- **Bridge только через `src/platform/`.** Никаких `bridge.*` в других местах. В тестах подставляется `FakePlatform`.
- **Баланс только в `src/data/`.** Магические числа в коде запрещены.
- **Хранение только `bridge.storage`.** `localStorage`, `sessionStorage`, IndexedDB, cookies запрещены (линт-правило + e2e-проверка).
- **Никаких внешних URL**, кроме `bridge.playgama.com`. Никаких аналитик кроме `bridge.analytics`.
- **Не использовать Esc**, эмодзи вместо иконок, `async`/динамическую загрузку Bridge.
- **Тема без азарта.** Нет слов casino/bet/jackpot/slot, ставок, платной валюты. Проверяется тестом на строки локализации.
- Не создавай новые зависимости без записи в `DECISIONS.md`.
- Маленькие коммиты: один критерий или одна подзадача на коммит. Сообщения по Conventional Commits.
- Не ослабляй и не удаляй тесты, чтобы «позеленело». Если тест неверен, правь спецификацию.

## Определение готовности (DoD)
- Все связанные `AC-*` покрыты автотестами и зелёные.
- `npm run verify` проходит без warning.
- Нет `console.error` в штатном сценарии.
- Доки и `ROADMAP.md` обновлены.
- Для изменений рендера: приложены скриншоты по матрице размеров из `TEST_PLAN.md`, и ты их просмотрел.

## Стек и команды
- Vite + TypeScript (strict) + three.js, Vitest (unit), Playwright (e2e, скриншоты).
- `npm run dev` / `build` / `verify` / `test` / `test:e2e` / `package` (создаёт `game.zip`).
- Режим отладки `?debug` и хуки `window.__game` описаны в `ARCHITECTURE.md`.

## Что делать, если застрял
Остановись, опиши проблему и варианты в `DECISIONS.md` (статус `proposed`), задай вопрос владельцу. Не обходи требования модерации.
